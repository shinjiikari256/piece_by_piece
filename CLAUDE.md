# «По кусочкам» — заметки для разработки

Браузерная 2D-игра-расследование (право: учебные дела по разным отраслям) + конструктор дел.
TypeScript · Vite 7 (одна страница `apps/client/index.html`: сайт, игра и конструктор `#/editor` — грузится отдельным куском, в офлайн-файле его нет; `apps/client/public/editor.html` — перенаправление со старого адреса) · React 19 (UI) · Phaser 3.90 (поле) · Zod 4 · vitest. Монорепо: `apps/client` (игра и конструктор), `apps/server` (API: `src/`, `drizzle.config.ts`), `shared/` и `scripts/` — в корне, один `package.json`. Сервер: Hono + PostgreSQL 16 + Drizzle (`apps/server/src/`). Без сервера игра работает как раньше (localStorage).

## Команды
- `pnpm typecheck` — после каждой правки кода (быстро, без вывода = ок).
- `pnpm lint` — ESLint (в т.ч. запрет нативного `<select>`). `pnpm test:e2e` — сквозные тесты в браузере (`e2e/`, playwright-core, свой Vite + сервер на PGlite; Chromium из `~/.cache/ms-playwright` или `PLAYWRIGHT_CHROMIUM`). CI — `.github/workflows/ci.yml`.
- `pnpm test` — vitest (корневой `vitest.config.ts`, клиент и сервер), `apps/client/src/game.test.ts` + `apps/client/src/editor/editor.test.ts` (валидность дел, баллы, прохождения).
- `pnpm build` — в конце задачи.
- `pnpm touch:cases [file]` — ОБЯЗАТЕЛЬНО после правки `apps/client/src/content/cases/*.json` (обновляет `updatedAt`; старые сохранения игроков получат предупреждение).
- `pnpm validate:cases` — проверка дел вне тестов.
- `pnpm audit:colors` — аудит цветов в стилях: литералы вне токенов, неопределённые `var(--…)`, сырая палитра в компонентах, полнота наборов тонов, темы (код возврата 1 при ошибках). Запускать после правок стилей и токенов.
- `pnpm generate:licenses` — ОБЯЗАТЕЛЬНО после смены `dependencies` (обновляет `apps/client/public/licenses.txt` — уведомления о лицензиях клиентских зависимостей; в `dist` файл копируется сам, в офлайн-файл вшивается комментарием; тест падает, если пакета нет).
- Сервер: `pnpm db:up` (PostgreSQL в Docker, порт 5433) → `ADMIN_LOGIN=admin ADMIN_PASSWORD=admin12345 pnpm server:dev` (API :8787; Vite проксирует `/api`). `pnpm db:generate` — миграция после правки `apps/server/src/db/schema.ts`. Целиком: `docker compose up --build`.
- `pnpm export:offline [--cases=case-001,./delo.json] [--out=delo.html] [--no-build]` — офлайн-файл: шаблон `vite build --mode offline` (`offline/.template/offline-template.html`, без дел) + вшитые дела → `offline/<--out>` (по умолчанию `offline/delo.html`).
- Dev для проверки в браузере: `pnpm dev --port 5199 --strictPort` в фоне; остановить:
  `ps -eo pid,args | grep "[v]ite.js --port 5199" | awk '{print $1}' | xargs -r kill -9`

## Где что
- `shared/api.ts` — контракт HTTP API (Zod-схемы запросов, типы ответов, роли/статусы, текст согласия).
- `apps/server/src/`: `app.ts` (сборка Hono, сессия из cookie), `http.ts` (ошибки, права `requireUser/Staff/Admin`, cookie), `routes/auth.ts` (регистрация, вход, пароль, ссылки), `routes/admin.ts` (пользователи с массовой правкой, группы, ссылки, настройки; права преподавателя — свои группы + без группы), `db/schema.ts`, `auth.ts` (Argon2id, сессии — SHA-256 токена), `main.ts`. Тесты `apps/server/src/server.test.ts` — PGlite (PostgreSQL в памяти), Docker не нужен.
- `apps/client/src/state/account.ts` — клиент API и стор учётной записи (`server: unknown|online|none`), `?join=<token>`; `apps/client/src/ui/account.tsx` — вход/регистрация/смена пароля; `apps/client/src/editor/AdminGate.tsx` — вход в конструктор; `apps/client/src/editor/EditorRoute.tsx` — раздел сайта (окна `DialogHost` — одни, в `App.tsx`; у конструктора своё меню правой кнопки, игровое на `#/editor` выключено).
- Сайт вокруг игры: `apps/client/src/ui/router.ts` (hash-маршруты `#/`, `#/cases`, `#/results`, `#/howto`, `#/login`, `#/register`, `#/account`, `#/admin/users[/id]|groups|settings`), `apps/client/src/ui/site.tsx` (шапка с меню пользователя, главная, дела, результаты, личный кабинет), `apps/client/src/ui/admin.tsx` (пользователи, карточка со статистикой, группы и ссылки, настройки), `apps/client/src/ui/results.tsx` (таблица и пагинация), `apps/client/src/ui/results-page.tsx` («Результаты»: фильтры дело/группа/пользователь, «Статистика» — `shared/results-stats.ts`), `apps/client/src/ui/modal.tsx` (окно поверх сайта), `apps/client/src/ui/documents.ts` (грамота и результат в PDF: холст → JPEG → свой PDF-писатель, без библиотек), стили — `apps/client/src/styles/site/*.css`. Вступление и результат — окна-папки поверх сайта (`SiteOverlay` в `App.tsx`, вкладки + крестик); в игре окно «Дело» — `TabbedModal` из `common.tsx`. Папки остаются только у дел (список, вступление). `store.screen === "menu"` — показывается сайт; смена адреса на вступлении/результате возвращает на сайт.
- `shared/` — общий код клиента и сервера: `case.ts` (Zod-схема дела), `conditions.ts`, `scoring.ts`, `public-case.ts` (`toPublicCase` — дело без ответов), `judge.ts` (судья: проверка сопоставлений, подсказки, итог, интерфейс `CaseAuthority`).
- `shared/migrate.ts` — версии форматов и миграции: дело (`formatVersion`, `parseCase` — единственный вход разбора дел), сохранение (`v`). Ломающая правка схемы дела → `CASE_FORMAT_VERSION` + звено в `caseMigrations` + `pnpm touch:cases`.
- `shared/case.ts` — Zod-схема дела = источник истины. Формы конструктора строятся из неё (`z.toJSONSchema`) — новое поле сразу появляется в редакторе; подписи/подсказки полей — `LABELS`/`HINTS`/`ENUM_LABELS` в `apps/client/src/editor/SchemaForm.tsx`.
- `apps/client/src/content/validate.ts` — целостность дела (ссылки, карта, баллы = 100, пары сопоставлений, цепочки без циклов). Сообщения вида `evidence x: …`, `location l/door d: …` — их разбирает `apps/client/src/editor/errors.ts` для перехода к ошибке.
- `apps/client/src/content/cases/case-001.json`, `case-002.json` — дела. Каталога прав нет: права — варианты вопроса `right` в самом деле; `generate:case --topic="…"` принимает тему свободным текстом.
- `apps/client/src/state/store.ts` — стор игры (`useSyncExternalStore`), `actions.*`, автосохранение; `persistence.ts` — сохранения, `profile.ts` — профиль/результаты.
- `shared/scoring.ts` — баллы, бонус за время (порог `minScore` в баллах, по умолчанию 75).
- Игра видит только `PublicCase` (`store.caseFile`): ответы, тексты выводов, тексты подсказок и разбор приходят от судьи (`apps/client/src/content/local-authority.ts`, позже — API) и лежат в `store.conclusions/hints/debrief`. Дело для игры — `caseRepository.open(id)`; полное `get(id)` — только конструктору.
- `apps/client/src/game/OfficeScene.ts` — сцена Phaser (движение, клики, двери, выходы, NPC, очные ставки; со стором не связана — только через `SceneHost` из `host.ts`, реализация `state/scene-host.ts`); `art/` (`tiles`, `sprites`, `doors`, `characters`) — весь процедурный пиксель-арт (тайлы, спрайты, двери, персонажи, `LOOKS`); `bridge.ts` — мост сцена↔React; `PhaserGame.tsx` — обёртка. Цикл Phaser не усыплять под окнами: во встроенном браузере VS Code без кадров холста страница перестаёт перерисовываться.
- `apps/client/src/ui/` — экраны: `screens.tsx` (список дел-папок, вступление, «Как играть»), `GameView.tsx` (шапка/панель/таймер), `panels.tsx` (осмотр, диалог, подсказки), `journal.tsx` (окно «Дело»: материалы, фильтры, сопоставление, фигуранты, закон), `verdict.tsx`, `common.tsx`, `contextmenu.tsx`, `notes.tsx`, `icons.tsx` (свои SVG — не эмодзи).
- `apps/client/src/editor/` — конструктор: `state.ts` (стор, undo/redo, сохранение, `screen: home|case`), `EditorApp.tsx` (шапка, стартовая страница, разделы-списки, очные ставки, улики, закон, решение), `SchemaForm.tsx` (генерик-формы) + `fields/` (условия и флаги, эффекты, чипы-ссылки, медиа), `sections/` (разделы конструктора), `DialogueGraph.tsx`, `MapEditor.tsx`, `LookEditor.tsx`, `refs.ts` (куда вести по id), `keys.ts` (ключи из названий через `transliteration`, ключ дела — из номера).
- `working/plans/PLAN.md` — единый план (что делаем сейчас, напоминания, на будущее; отмечать `[x]` по готовности) и справка по офлайн/онлайн-архитектуре. Название игры — «По кусочкам» (плашки «Не раскрыто» остаются); технические ключи `pokusochkam:*` пока прежние, смена — в плане.

Большие файлы (`OfficeScene.ts`, `EditorApp.tsx`, `SchemaForm.tsx`, `MapEditor.tsx`, `game/art/sprites.ts`) не читать целиком: `grep -n "^function\|^export\|^const [A-Z]"` → читать нужный диапазон.

## Структура крупных модулей
- `ui/journal/` (index + materials, match, characters, law), `ui/admin/` (index + users, groups, settings), `ui/verdict/` (final — окно решения, result, downloads), `ui/documents/` (common, certificate, result, pdf; публичный API — `index.ts`).
- `editor/map/` — редактор карты: `types`, `canvases` (кэши холстов), `render` (`renderMap`), `helpers`, `panels`, `Palette`; сам `MapEditor.tsx` — состояние и мышь. `editor/labels.ts` — подписи и подсказки полей форм.
- `game/art/sprites/` — предметы по группам: `furniture`, `office`, `wall`, `household`, `court`, `commerce`, `medical`, `street` (файл на группу, `index.ts` собирает `SPRITES` и `SPRITE_GROUPS`; подписи — `SPRITE_NAMES` в `tiles.ts`; ключ нового предмета — ещё и в `SpriteKey` в `shared/case.ts`). Тест `sprites.test.ts` следит, что каждый ключ описан ровно в одной группе, имеет название и рисует внутри своих размеров. Подгруппы клеток — `FLOOR_GROUPS`/`WALL_GROUPS` в `tiles.ts`.
- `game/scene/` — части сцены без привязки к Phaser-сцене: `navigation` (чистые поиск пути, столкновения, подтяжка к проёмам; есть тесты), `textures`, `types`.
- Кнопка одна на весь интерфейс (`.btn` в `styles/app/base.css`); оси независимы: тон (`btn--primary`, `btn--danger`, `btn--danger-solid`), размер (`btn--sm`, `btn--big`), ширина (`btn--block`), форма (`btn--icon`). Своих семейств вроде `.mini-btn` не заводить: нужно новое состояние — новый модификатор.
- Поля `input`/`textarea` стилизованы самими тегами в `styles/app/base.css` через `:where()` (нулевая специфичность): в компонентах задавать только отличия (размер, рамка, ширина), не копировать рамку, радиус, фон и кольцо фокуса; `!important` для этого не нужен.
- Служебные классы в `styles/app/base.css`: `.ellipsis` (обрезка строки многоточием), `.list-reset` (список без маркеров и отступов) — копии этих свойств в правилах компонентов не плодить.
- Цвета — два слоя: сырая палитра `--pal-*` (`styles/tokens/palette.css`) и роли (`--bg-*`, `--text-*`, `--border-*`, тона `--accent|good|warn|bad|evidence|testimony|conclusion` + `-soft/-line/-strong/-ink`, `styles/tokens/roles.css`). В компонентах — только роли; тема переопределяет роли (`styles/themes/salad.css`, включается `?theme=salad`). Составные значения (тени `--elev-*`, кольца) — `tokens/effects.css`.
- Состояния и тоны — атрибутами, не классами-модификаторами: тон `data-tone="good|warn|bad|accent|evidence|testimony|conclusion"` (`styles/app/tone.css`, оформление через `--tone*`; значения для настроений/достоверности/статусов — `ui/tone.ts`), «выбрано» `data-selected`, «включено» `aria-pressed`, вкладка `aria-selected`, текущий пункт `aria-current`, раскрыто `aria-expanded`/`data-open` (`styles/app/states.css`). Раскладки — `.row`, `.stack`, `.pair` (`styles/app/base.css`, расстояние `--gap`).
- Стили: общие и крупные — `styles/app/*.css`, `styles/site/*.css` (порядок подключения задаёт каскад: список в `styles/index.css`, его импортирует `main.tsx`), конструктор — `editor/styles/*.css` (`editor/styles/index.css`, его импортирует `EditorRoute.tsx`). Стили, которые не пересекаются с другими файлами, лежат рядом с компонентом и импортируются в нём (`ui/loader.css`, `ui/contextmenu.css`, `ui/case-stamps.css`, `editor/Tabs.css`, `editor/sections/Law.css`); новый компонент со своими стилями — так же. Перед переносом остальных файлов проверять конфликты: одинаковый селектор и свойство в разных файлах = зависимость от порядка.

## Окна-папки (единый стиль)
- Полоса закладок — один компонент `apps/client/src/ui/folder.tsx` (`FolderTabs`: «назад», вкладки, крестик справа; единственная вкладка всегда выглядит активной). Им пользуются все папки.
- В игре окна — `TabbedModal` (`ui/common.tsx`; `tone="blue"` — решение, `size="narrow"` — подсказки/заметки/осмотр; вокруг лист `.modal`): журнал, подсказки (`HintsPanel`), заметки (`NotesWindow`, `ui/notes.tsx`), осмотр (`ObjectPanel`), «Как играть» (`HowToWindow`, `ui/screens.tsx`, и в игре, и на сайте), решение (`FinalScreen`, `ui/verdict.tsx`). Диалог (`DialogueWindow`) — `FolderTabs` над листом, прижат к низу. Страницы сайта — `Folder` (`screens.tsx`). Новые окна делать через них. Подложка — `Backdrop`, небольшие диалоги (подтверждение, форма) — `Dialog`, оба в `ui/window.tsx` (стили `styles/app/window.css`); подтверждения кодом — `ask()`/`tell()` из `ui/dialog.tsx`.
- Esc: слои (`TabbedModal`, `Dialog`, выпадающий `Select`) подписываются через `useEscape` (`ui/hooks.ts`) — Esc получает только верхний слой; остальное (диалог-окно разговора, вступление, результат) обрабатывает `App.tsx`.
- Логотип — `ui/logo.tsx` (`Logo` в шапке, `LogoArt` на главной); большая иллюстрация — самостоятельный `assets/logo-detailed.svg` (анимация внутри, обложка меняет контур через CSS `d`, не transform).


## Подводные камни
- В шелле `NODE_ENV=production` — dev-хуки включаются по `import.meta.env.MODE === "development"`: `window.__game = { actions, store }`, `window.__editor = { editor, editorStore }` (после открытия `#/editor`).
- `apps/client/vite.config.ts`: любая правка TS → полная перезагрузка страницы (HMR сторов давал две копии состояния). CSS — на лету.
- Конструктор (`#/editor`): с сервером — учётная запись преподавателя/админа; без сервера открыт только в `pnpm dev` (`DEV_EDITOR` в `apps/client/src/env.ts`), в сборке без сервера его нет. Вход — папка `#/login | #/register | #/guest` (`AuthPage` в `apps/client/src/ui/account.tsx`).
- `apps/client/src/env.ts`: `OFFLINE` (`--mode offline`: без конструктора, черновиков, тестового запуска), `GAME_VERSION`, `storageKey()` — все ключи игры через него (в офлайн-файле с префиксом `offline:<buildId>:`).
- Весь localStorage — только через `src/state/storage.ts` (`readJson/writeJson/removeKey/listKeys`, `onWriteFailed`); запись возвращает `false`, если браузер её не принял — вызывающий обязан это показать (конструктор — плашка, игра — тост); ключи сами подставляют `storageKey()`.
- Название игры — `shared/brand.ts` (`APP_NAME`).
- Ключи localStorage: `pokusochkam:save:<caseId>`, `:draft:<id>`, `:playtest`, `:editor:current|saved`, `:results`, `:profile`, `:session`.
- Ключ материала в UI: id улики или `fact:<deductionId>`; `deduction.evidenceIds` — ровно 2 id (улики или факты).
- Клавиша взаимодействия (E/Enter/Пробел) ловится на `window` в capture-фазе, не из очереди Phaser: очередь срабатывает в следующем кадре и снова открывала только что закрытое окно.
- Необязательные поля форм конструктора по умолчанию рисуются кнопкой «+ Поле» (`ObjectFields`). Чтобы поле было сразу видно, пометить его в схеме `.meta({ always: true })`: пустое значение тогда просто не пишется в дело (`isBlank` в `SchemaForm.tsx`). Двери — свой блок `DoorFields` («Закрыта» → текст и условия, `editor/map/panels.tsx`).
- Флаги — сущность `CaseFile.flags` ({id, name}); у каждого используемого флага должно быть название (валидатор). «Закон» — `lawReference.basis/notes`, без каталога.
- Повторов в диалогах нет: повторный выбор просто снова ведёт к ответу; разные реакции автор строит флагами. ✓ у заданных вопросов — только подсказка.
- Ключи (id) никогда не меняются сами: только вручную в `KeyField`; у сущностей верхнего уровня — с подтверждением и заменой всех ссылок (`renameKey` в `apps/client/src/editor/keys.ts`).
- Пользователь играет во встроенном браузере VS Code (Linux): нативные `<select>` там не открываются, перерисовка капризна — избегать `transform` на hover и трюков с остановкой анимации.
- Не использовать нативный `<select>` — только `apps/client/src/ui/Select.tsx` (или свои меню).
- Вкладки в конструкторе — один компонент `apps/client/src/editor/Tabs.tsx` (`variant="bar"|"inline"`, стили `editor/styles/tabs.css`); своих `*__tab` не заводить.
- Боковые списки разделов конструктора (персонажи, улики, флаги, диалоги…) — `apps/client/src/editor/EntityList.tsx` (`renderItem`, `tools`, `ItemText`); свои `<ul className="ed__list">` не писать.
- Тексты интерфейса — по-русски; протагонист — дознаватель.

## Проверка в браузере
playwright-core + `~/.cache/ms-playwright/chromium_headless_shell-1234/chrome-headless-shell-linux64/chrome-headless-shell` (передать в `chromium.launch({ executablePath })`). Скрипты держать в scratchpad, не в репозитории. Состояние удобно задавать через `window.__game.actions` (`interact("npc_alina")`, `choose(id)`, `close()`); СКРИНШОТЫ НЕ ДЕЛАТЬ после правок вёрстки/стилей и «для проверки вида» — проверять typecheck/lint/тестами/сборкой и запросами к DOM или стору; скриншот — только если иначе не узнать (баг отрисовки) или попросил пользователь, и перед ним одной строкой сказать зачем; не более одного на задачу (общее правило — в глобальном CLAUDE.md). Карта дела 1 при 1500×900: поле ≈ x 55…1445, y 52…840, тайл ≈ 46 px.
