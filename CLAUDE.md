# «По кусочкам» — заметки для разработки

Браузерная 2D-игра-расследование (право: учебные дела по разным отраслям) + конструктор дел.
TypeScript · Vite 7 (одна страница `apps/client/index.html`: сайт, игра и конструктор `/editor` — грузится отдельным куском, в офлайн-файле его нет; `apps/client/public/editor.html` — перенаправление со старого адреса) · React 19 (UI) · Phaser 3.90 (поле) · Zod 4 · vitest. Монорепо: `apps/client` (игра и конструктор), `apps/server` (API: `src/`, `drizzle.config.ts`), `shared/` и `scripts/` — в корне, один `package.json`. Сервер: Hono + PostgreSQL 16 + Drizzle (`apps/server/src/`). Без сервера игра работает как раньше (localStorage).

## Команды
- `pnpm typecheck` — после каждой правки кода (быстро, без вывода = ок).
- `pnpm lint` — ESLint (в т.ч. запрет нативного `<select>`). `pnpm test:e2e` — сквозные тесты в браузере (`e2e/`, playwright-core, свой Vite + сервер на PGlite на каждый воркер, порты 5300+/8900+ по номеру воркера; файлы по очереди; Chromium из `~/.cache/ms-playwright` или `PLAYWRIGHT_CHROMIUM`). CI — `.github/workflows/ci.yml`.
- `pnpm test` — vitest (корневой `vitest.config.ts`, два project: клиент и сервер; по отдельности — `pnpm test:client` / `pnpm test:server`; БД серверных тестов — `memoryDb()` поднимает PGlite из снимка с миграциями), `apps/client/src/game*.test.ts` (прохождения, диалоги, области, эффекты) + `apps/client/src/content/*.test.ts` (по темам: moveTo, области, миграции, переменные, условия, эффекты, проверки) + `apps/client/src/editor/editor.test.ts` (валидность дел, баллы).
- `pnpm build` — перед `pnpm test` (так и в CI: typecheck → lint → build → validate:cases → test).
- `pnpm touch:cases [file]` — ОБЯЗАТЕЛЬНО после правки `apps/client/src/content/cases/*.json` (обновляет `updatedAt`; старые сохранения игроков получат предупреждение).
- `pnpm validate:cases` — проверка дел вне тестов.
- `pnpm audit:colors` — аудит цветов в стилях: литералы вне токенов, неопределённые `var(--…)`, сырая палитра в компонентах, полнота наборов тонов, темы (код возврата 1 при ошибках). Запускать после правок стилей и токенов.
- `pnpm generate:licenses` — ОБЯЗАТЕЛЬНО после смены `dependencies` (обновляет `apps/client/public/licenses.txt` — уведомления о лицензиях клиентских зависимостей; в `dist` файл копируется сам, в офлайн-файл вшивается комментарием; тест падает, если пакета нет).
- Сервер: `pnpm db:up` (PostgreSQL в Docker, порт 5433) → `ADMIN_LOGIN=admin ADMIN_PASSWORD=admin12345 pnpm server:dev` (API :8787; Vite проксирует `/api`). `pnpm db:generate` — миграция после правки `apps/server/src/db/schema.ts`. Целиком: `docker compose up --build`.
- `pnpm export:offline [--cases=case-001,./delo.json] [--out=delo.html] [--variant=editor] [--no-build]` — офлайн-файл: шаблон `vite build --mode offline` (`--mode offline-editor` — с конструктором, `OFFLINE_EDITOR` в `env.ts`; на сервере — страница `/offline`, `routes/admin/offline.ts`, шаблоны из `OFFLINE_DIR`, вшивание — `shared/offline-embed.ts`) (`offline/.template/offline-template.html`, без дел) + вшитые дела → `offline/<--out>` (по умолчанию `offline/delo.html`). Вариант «только игра» вшивает только спрайты, стоящие в делах (`embedSprites`, данные — `apps/client/src/game/art/sprites/data`; в шаблоне «игры» `SPRITE_GROUPS` пуст, `SPRITES` берётся из `embedded.ts`).
- `pnpm offline:templates` — шаблоны `offline/server/game.html` и `editor.html` для страницы `/offline` в дев-режиме (в Docker их собирает этап `offline`); вне production `server:dev` берёт их оттуда сам, иначе `OFFLINE_DIR`.
- Dev для проверки в браузере: `pnpm dev --port 5199 --strictPort` в фоне; остановить:
  `ps -eo pid,args | grep "[v]ite.js --port 5199" | awk '{print $1}' | xargs -r kill -9`

Тесты `apps/server/src/server.test.ts` — PGlite (PostgreSQL в памяти), Docker не нужен.

Онлайн-код грузится динамически только при `!OFFLINE` и не попадает в офлайн-сборку: `ui/pages/online.tsx` (страницы входа, кабинета, админки, шапка пользователя), `ui/components/results-server.tsx`, `editor/publish.ts`, `editor/RemoteCases.tsx`; `ui/pages/account.tsx` — вход/регистрация/смена пароля; `apps/client/src/ui/pages/account.tsx` — вход/регистрация/смена пароля; `apps/client/src/editor/AdminGate.tsx` — вход в конструктор; `apps/client/src/editor/EditorRoute.tsx` — раздел сайта (окна `DialogHost` — одни, в `App.tsx`; у конструктора своё меню правой кнопки, игровое на `#/editor` выключено).
- Сайт вокруг игры: `apps/client/src/ui/lib/router.tsx` (обычные адреса `/`, `/cases`, `/results`, `/howto`, `/login`, `/register`, `/account`, `/play/<дело>`, `/playtest`, `/admin/users[/id]|groups|settings`, `/editor[/дело[/раздел]]` — положение конструктора синхронизирует `editor/url.ts` (`useEditorUrl`; выбранный элемент и вкладка раздела — `useUrlParam`: `?item=`, `?tab=`, на карте `?obj=`, в диалогах `?node=`; новое состояние раздела, которое должно переживать перезагрузку, хранить так же); `Link`, `navigate`, `useRoute`, `useSearchParam`; у офлайн-файла с диска тот же набор после `#` — `#/cases`; ссылки в разметке — только `Link`/`href()`, не `href="#/…"`; онлайн-сборка собирается с `base: "/"`, офлайн — с `./`; сервер должен отдавать `index.html` на любой путь — Caddy `try_files {path} /index.html`), `apps/client/src/ui/pages/site.tsx` (шапка с меню пользователя, главная, дела, результаты, личный кабинет), `apps/client/src/ui/admin.tsx` (пользователи, карточка со статистикой, группы и ссылки, мероприятия — `admin/events.tsx`, настройки), `apps/client/src/ui/components/results.tsx` (таблица и пагинация), `apps/client/src/ui/pages/results-page.tsx` («Результаты»: фильтры дело/группа/пользователь, «Статистика» — `shared/results-stats.ts`), `apps/client/src/ui/modal.tsx` (окно поверх сайта), `apps/client/src/ui/documents.ts` (грамота и результат в PDF: холст → JPEG → свой PDF-писатель, без библиотек), стили — `apps/client/src/styles/site/*.css`. Вступление и результат — окна-папки поверх сайта (`SiteOverlay` в `App.tsx`, вкладки + крестик); в игре окно «Дело» — `TabbedModal` из `common.tsx`. Папки остаются только у дел (список, вступление). Расследование в адресе — `ui/lib/game-route.ts` (`useGameRoute`): вступление/игра/решение живут на `/play/<дело>` (тестовый запуск — `/playtest`), перезагрузка открывает дело через `resume`, «назад» из игры открывает окно «Выход». `store.screen === "menu"` — показывается сайт; смена адреса на вступлении/результате возвращает на сайт.
- Онлайн-правила (сводка): админ = максимальный доступ, в списках доступа (преподаватели групп, соавторы дела, группы мероприятий) его не указывают. Группы создаёт и преподаватель (становится её преподавателем); у ссылки группы `auto_approve`. Правка дел на сервере — автор, админ и соавторы (`case_editors`, `GET/PUT /admin/cases/:id/editors`); `PUT /admin/cases/:id?base=<versionId>` → 409 `version_conflict`. API-токены админа (`api_tokens`, `Authorization: Bearer pbp_…`) дают только `GET/PUT /api/admin/cases/:id`. Итог ≤ суммы баллов дела (бонус за время компенсирует штрафы, не сверх максимума). Локальные сохранения, результаты и профиль привязаны к пользователю (`storageKey`: префикс `u<id>.` для `save:|results|profile`, гость — прежние ключи). Результаты удаляют админ (любые) и преподаватель (студентов своих групп): `POST /results/delete`, `DELETE /results/:id` — вместе с попыткой, чтобы зачётная попытка освободилась.
- Мероприятия: фильтр `event` (`ResultsQuery`: id или `none`) работает в списке, статистике и CSV; в строках результата `event` — метка; `GET /admin/events/:id/participants` — студенты групп мероприятия и статус по каждому делу (`none|active|done`, лучший балл); у студента `GET /events` отдаёт `doneByCase` и `bestByCase`; у мероприятия `publishAt` (видно студентам с этого момента, раньше его для них нет), `opensAt` (начало: до него студенту список дел скрыт — `caseIds: []`, а `studentCaseIds` не открывает дела), `requiredCases` (сколько дел достаточно; нет — все; `required` — итоговое), у персонала `participants/passed`. Клиент: `/admin/events/<id>/results` (`pages/admin/event-results.tsx`: QR на `/events/<id>`, участники, `ServerResults eventId=…`), вкладка студента `/events[/<id>]` (`pages/events-page.tsx`); не вошедшего страница отправляет на `/login` и возвращает назад (`setReturnTo/takeReturnTo` в `state/api.ts`). QR — `ui/components/qr.tsx`. Список мероприятий один для всех ролей — `/events` (`pages/events-page.tsx`; у персонала кнопка «Создать» и кнопки-иконки: результаты/QR, ссылка, изменить, удалить); `/admin/events` без id перенаправляет туда, форма и результаты — `/admin/events/new|<id>[/results]`. «Мероприятия» — пункт шапки для всех вошедших; «Конструктор дел» с сервером — в меню пользователя (в шапке только у `DEV_EDITOR` без сервера).
- `shared/` — общий код клиента и сервера: `case.ts` (Zod-схема дела), `conditions.ts`, `scoring.ts`, `public-case.ts` (`toPublicCase` — дело без ответов), `judge.ts` (судья: проверка сопоставлений, подсказки, итог, интерфейс `CaseAuthority`).
- `shared/migrate.ts` — версии форматов и миграции: дело (`formatVersion`, `parseCase` — единственный вход разбора дел), сохранение (`v`). Ломающая правка схемы дела → `CASE_FORMAT_VERSION` + звено в `caseMigrations` + `pnpm touch:cases`.
- `shared/case.ts` — Zod-схема дела = источник истины. Формы конструктора строятся из неё (`z.toJSONSchema`) — новое поле сразу появляется в редакторе; подписи/подсказки полей — `LABELS`/`HINTS`/`ENUM_LABELS` в `apps/client/src/editor/SchemaForm.tsx`.
- `apps/client/src/content/validate.ts` — целостность дела (ссылки, карта, баллы = 100, пары сопоставлений, цепочки без циклов). Сообщения вида `evidence x: …`, `location l/object o: …` — их разбирает `apps/client/src/editor/errors.ts` для перехода к ошибке.
- `apps/client/src/content/test-cases/*.json` — тестовые дела для разработки (в сборку и офлайн-файл не попадают, видны только в `pnpm dev` и тестах); `case-test-moveto` — копия дела 2 с пунктом «[ТЕСТ] Перемещения персонажей» в разговоре с Тимуром (там же пункты 7–10: счётчик, начальный флаг, «или») и пунктом «[ТЕСТ] Новые возможности» (ветка `n_menu`: эффекты варианта, сообщения, `once`, `requires` у эффекта, границы счётчика, перечисление «сейф», предмет-ключ и расход, составное условие, ящик с тремя предметами у старта, область «Режимы» рядом со стартом, события вестибюля и ошибки сопоставления, `startDialogue`, `travel`, `failCase`); новые сценарии задач добавлять туда же.
- `apps/client/src/content/cases/case-001.json`, `case-002.json` — дела. Каталога прав нет: права — варианты вопроса `right` в самом деле; `generate:case --topic="…"` принимает тему свободным текстом.
- `apps/client/src/state/store.ts` — стор игры (`useSyncExternalStore`), `actions.*`, автосохранение. Ядро не знает среду: сохранения и результаты — через `state/platform.ts` (`platform().saves/results`, асинхронно; подключается `setPlatform` в `main.tsx`: `browser-platform.ts` — `localStorage`, `online-platform.ts` — оболочка над ней: при входе сохранения ещё и на сервере (`/me/saves`), свежее выбирается по `savedAt`, `memory-platform.ts` — для тестов). Платформа даёт и экранам сайта: `saves.list/read/clear`, `results.list/clear`, `profile.read/write/subscribe`, `capabilities.offline` (вместо `OFFLINE` в экранах); экраны читают её асинхронно через `usePlatformValue`/`useProfile` (`state/platform-hooks.ts`). Хранилище браузера: `persistence.ts` (сохранения), `profile.ts` (профиль, результаты) — только внутри `browser-platform.ts`; чистые функции над сохранением — `save-data.ts`, над результатами — `result-record.ts`. Новый код ядра и экранов в `localStorage`/`persistence`/`profile` напрямую не ходит.
- `shared/scoring.ts` — баллы, бонус за время (порог `minScore` в баллах, по умолчанию 75).
- Игра видит только `PublicCase` (`store.caseFile`): ответы, тексты выводов, тексты подсказок и разбор приходят от судьи (`apps/client/src/content/local-authority.ts`, позже — API) и лежат в `store.conclusions/hints/debrief`. Дело для игры — `caseRepository.open(id)` (вошедший игрок — `ApiAuthority` с сервера, гость и офлайн — `LocalAuthority`; черновики конструктора всегда локальные); полное `get(id)` — только конструктору.
- `apps/client/src/game/OfficeScene.ts` — сцена Phaser (движение, клики, двери, области-триггеры, NPC; со стором не связана — только через `SceneHost` из `host.ts`, реализация `state/scene-host.ts`); `art/` (`tiles`, `sprites`, `doors`, `characters`) — весь процедурный пиксель-арт (тайлы, спрайты, двери, персонажи, `LOOKS`); `bridge.ts` — мост сцена↔React; `PhaserGame.tsx` — обёртка. Цикл Phaser не усыплять под окнами: во встроенном браузере VS Code без кадров холста страница перестаёт перерисовываться.
- `apps/client/src/ui/` — четыре слоя, импорт только «вниз» (pages → components → kit/lib):
  - `kit/` — UI-компоненты без знания об игре и API: `Select`, `DateTimePicker`, `window` (`Backdrop`, `Dialog`), `dialog` (`ask`/`tell`), `alert`, `folder` (`FolderTabs`), `loader`, `logo`, `icons` (свои SVG — не эмодзи), `contextmenu`, `md`, `credit`.
  - `components/` — компоненты предметной области: `common` (`TabbedModal`), `panels` (осмотр, диалог, подсказки), `notes`, `GameView` (шапка/панель/таймер), `site-nav`, `results*`, `zoom-control`, `game-zoom`, `journal/`, `verdict/`, `offline/` (хук `useOfflineBuild` и строки выбора).
  - `pages/` — страницы по адресам: `screens` (список дел-папок, вступление, «Как играть»), `site`, `account`, `results-page`, `offline-page`, `online`, `admin/`.
  - `lib/` — не визуальное: `router`, `theme`, `keyboard`, `game-route`, `hooks`, `tone`, `table-rows`, `documents/`.
  Новый файл кладётся в слой по тому, что он знает: ничего об игре — `kit/`, знает игру или API, но не адрес — `components/`, привязан к адресу — `pages/`. Страницу не импортируют из компонентов (кроме ленивых `import()` онлайн-кода).
- `apps/client/src/editor/` — конструктор: `state.ts` (стор, undo/redo, сохранение, `screen: home|case`), `EditorApp.tsx` (шапка, стартовая страница, разделы-списки, улики, закон, решение), `SchemaForm.tsx` (генерик-формы) + `fields/` (условия и флаги, эффекты, чипы-ссылки, медиа), `sections/` (разделы конструктора), `DialogueGraph.tsx`, `MapEditor.tsx`, `LookEditor.tsx`, `refs.ts` (куда вести по id), `keys.ts` (ключи из названий через `transliteration`, ключ дела — из номера).
- `working/plans/ROADMAP.md` — порядок открытых работ (планы лежат рядом; `working/*` вне git; закрытый план удаляется, нужное переносится в `CLAUDE.md`/`docs/`; мелочи — `BACKLOG.md`, идеи — `IDEAS.md`, долг — `TECH_DEBT.md`); справка по офлайн/онлайн-архитектуре — `docs/ARCHITECTURE.md`. Название игры — «По кусочкам» (плашки «Не раскрыто» остаются); технические ключи `pokusochkam:*` пока прежние, смена — в плане.

Большие файлы (`OfficeScene.ts`, `EditorApp.tsx`, `SchemaForm.tsx`, `MapEditor.tsx`, `game/art/sprites.ts`) не читать целиком: `grep -n "^function\|^export\|^const [A-Z]"` → читать нужный диапазон.

## Сборка дел по приговорам
Любое новое дело (по приговору из `working/case_refs/`) собирать строго по `docs/CASE_AUTHORING.md`: порядок работы, состав дела (2 локации, 4–6 персонажей, 14–18 улик, 5–7 сопоставлений, 3 подсказки, 5 вопросов на 100 баллов, 5–7 событий), правила «ловушки», карты и диалогов, чек-лист. Карту и расстановку прошлого дела не копировать. Сборщик пишется скриптом `working/cases/build-case-NNN.cjs` (в `.gitignore`), образец — `build-case-004.cjs`; старт игрока задаётся только в одной локации на дело. `pnpm touch:cases` правит `updatedAt` у всех дел — после него откатить чужие (`git checkout`) и оставить только новое.

## Структура крупных модулей

Текущую локацию вызывающий обязан передать (стор — `state.locationId`), иначе `inLocation` не выполняется. Автор собирает условие в редакторе пронумерованными строками и формулой связки (`1 && (2 || 3)`, русские `и`/`или` тоже): разбор, строки↔дерево и правки — `shared/condition-formula.ts` (без отрицания групп и без повторов номеров; номера только в интерфейсе, после правки пересчитываются). JSON-схему для форм берёт `formSchema` (`editor/json-schema.ts`): ссылки `$ref` на рекурсивное условие заменяются заглушкой. Редактор — `fields/Conditions.tsx` (`ConditionEditor`).

- Перечисления: `CaseFile.enums` ({id, name, values:[{id,name}], initial?}), текущие значения в `Progress.enums` (заполняет `startProgress`, у старых сохранений — `sanitizeSave`), эффект `changeVariable` с `action: "assign"` и `valueId`, условие `enums: [{enumId, in?, notIn?}]`. Ключи флагов, счётчиков и перечислений общие (`isVariableKeyTaken`); поля-ссылки `variableId`/`enumId` обновляет `renameKey`; значения перечисления переименовываются и удаляются через `renameEnumValue`/`deleteEnumValue` (`editor/sections/Enums.tsx`).
- События с эффектами: `Location.onEnter` (вызывает стор в `enterLocation` — при старте и `travel`), `LocationObject.onInteract`, `Evidence.onCollect` (в `applyEffects` через `ctx.onCollect`, сразу после выдавшего эффекта), `Deduction.failEffects` (при каждой ошибке). Все срабатывают при каждом наступлении события; настройка `once` у эффекта — один раз за прохождение (ключ `once:<site>#<номер>` в `Progress.fired`, `site` передаёт `fxCtx(site)`). Все места учтены в `effectSites`.
- Эффекты `startDialogue`, `travel` (игрок в локацию, клетка x,y) и `removeEvidence`: `applyEffects` не меняет сцену, а возвращает `followUp` ({dialogueId, travel}) и `removedEvidence`; стор выполняет их в `announce` → `runFollowUp` (глубина ≤ 5 против зацикливания). Новый эффект с последствиями вне `Progress` строится так же. Эффект варианта `startDialogue` отменяет обычный переход `next`.
- Выбранные варианты ответа хранит `Progress.chosen` (ключ `choiceKey`: `диалог/узел/вариант`; отметка ✓ и условие `chosen: [{dialogueId, nodeId, choiceId, not?}]`); в файле сохранения дублируются в `usedChoices` для прежних сохранений. Условие `notInLocation` — игрок не в этих локациях.
- Материал `Evidence.kind`: `evidence` (улика), `testimony` (показания), `item` (предмет: ключ, фонарь — лежит в журнале, но не улика). Предметы выдаются и проверяются обычными эффектами/условиями, но не могут быть в сопоставлениях и вопросах про улики (валидатор); в режиме сопоставления журнал их скрывает, итоговый экран не показывает.
- Улики и прочие эффекты осмотра предмета — `LocationObject.onInteract` (эффект `addEvidence`); поля `interaction.evidenceId` больше нет (формат 8). Окно осмотра показывает уже выданные предметом материалы (`objectEvidenceIds`): одну улику — карточкой с кнопками «Важно/Неважно», несколько — списком с отметками. Источник улики в журнале и в конструкторе берётся из всех эффектов дела (`sourceOf`, `evidenceOrigins` через `effectSites`).
- Эффект `failCase` (`text?`) — неудачное завершение: `followUp.failCase`, стор стирает сохранение и открывает оверлей `failed` (окно «Дело провалено»: «Начать заново» — `restartAfterFail`, «К списку дел»), результат не пишется. Вариант разговора с таким эффектом дальше `next` не идёт.
- Человек на карте по условию: `NpcPlacement.requires` — сцена (`OfficeScene.syncNpcs`) убирает его сразу, когда условие не выполнено, и возвращает, когда выполнено; `store.interact` с отсутствующим человеком ничего не делает. Окно разговора, где скрыты все варианты, показывает «Закончить разговор» (`DialogueWindow`).
- Эффект `message` (`text`) показывает игроку тост: `applyEffects` возвращает его в `messages`, а стор показывает через `announce` вместе с новыми уликами — вызывающий код обязан передать `messages` в `announce`. Условия-отрицания: `notFlags`, `notFollowing`, `notEvidence`, `notDeductions`.
- Эффект может иметь `requires` (условие, проверяется в момент его очереди по состоянию после предыдущих эффектов списка); `applyEffects(effects, progress, ctx)` — `ctx` = `{ whereIs, counters, locationId }`, в сторе его собирает `fxCtx()`. Подпись эффекта для списков — `editor/fields/effect-label.ts`.
- Места с эффектами (реплики, **варианты ответа** `choice.effects`, сопоставления, осмотр предмета, действия областей «эффекты») перечисляет `effectSites`/`mapEffectSites` в `shared/effect-sites.ts` — валидатор, предупреждения, «где используется» флага и его удаление ходят только через него. Новое место с эффектами добавлять там же, а не в каждую проверку отдельно. Удаление и переименование переменных (флаг, счётчик, перечисление) идёт через один обход `walkVariables`/`deleteVariable` (`editor/fields/variable-walk.ts`): он сам находит эффекты и строки условий на любой глубине.
- Предмет: `interaction` (окно осмотра: текст и необязательная `evidenceId`) отделён от эффектов — они в `LocationObject.onInteract` (срабатывают при каждом осмотре; разово — `once` у эффекта). Предмет с `interaction: null` и непустым `onInteract` интерактивен без окна (`isInteractive`). «Предмет осмотрен» / «область посещена» отдельных условий не имеют — выражаются флагом, который ставит такой эффект или действие области «эффекты».
- Предъявление материала из журнала: `DialogueNode.presentations` (`{id, evidenceIds (пусто — любой), requires?, effects, next}`) — в окне разговора кнопка «Предъявить материал из журнала…» открывает список собранного; `actions.present(evidenceId)` берёт первое подходящее предъявление (эффекты → `next`), иначе тост «Собеседник не реагирует». Эффекты учтены в `effectSites` (`choiceId: present:<id>`). Поле необязательное — формат дела не менялся.
- Повторов в диалогах нет: повторный выбор просто снова ведёт к ответу; разные реакции автор строит флагами. ✓ у заданных вопросов — только подсказка.
- Очных ставок как сущности нет (формат 3): очная ставка — обычный диалог, подключённый участникам на карте как диалог по условию `NpcPlacement.dialogues` (`requires.following` — другой участник идёт за игроком; порядок списка важен, первый подходящий запускается, иначе `dialogueId`); настройка — у человека на карте (`map/NpcDialogues.tsx`). Миграция 2 → 3 переводит старые `confrontations`.
- Области (`Location.zones`: имя, ключ, клетки, `actions`; `Progress.fired`): область хранит упорядоченные действия `ZoneAction` — `dialogue`, `object` (взаимодействие с предметом), `effects` (применить эффекты без диалога), `exit` (переход в локацию `to` в точку `spawn`) — у каждого необязательные `requires`, `lockedText` (что сказать, если условие не выполнено — по E или при входе) и `trigger`: `use` (по E внутри области, по умолчанию), `enter` (при входе, один раз — `Progress.fired`), `enterEvery` (при каждом входе), `leave` (при выходе; для `exit` не допускается); срабатывает первое подходящее по порядку (`zoneAction(zoneId, режим)` в сторе). **Выходов `Location.exits` больше нет — выход это область с действием `exit`** (миграция формата 1 → 2 в `shared/migrate.ts`; старт игрока остаётся отдельно — `playerStart`). В игре — `OfficeScene.buildZones/watchZones`, в сторе — `zoneAction/runZoneAction/enterZone`; в конструкторе — инструмент «Область» на карте (мазок/Shift/Alt), панель области с действиями (`map/ZoneActions.tsx`) и блок «Запуск диалога» в диалогах (`fields/DialogueTrigger.tsx`: привязать область или создать на месте — `map/ZoneCreator.tsx`).
- Спутники (`progress.followers`): вручную отпускаются клавишей/кнопкой взаимодействия, когда рядом нечего трогать (в нижней панели она тогда «Отпустить спутников»; `actions.releaseFollowers` — как `returnHome` для всех); сами уходят домой через 3 с, если игрок вошёл в область, где ни одно действие не подходит (`enterZone` + `leaveZone`, таймер в сторе; вышел из области — таймер снят).
- Эффект `moveTo` (персонаж идёт на клетку; `shared/case.ts`, ход — `game/scene/walker.ts`, настройка — `editor/fields/Effects.tsx` + окно выбора клетки `editor/map/CellPicker.tsx`): итоговое место сразу пишется в `npcPlaces`, сцена ведёт NPC пешком; закрытый путь — откат и реплика `failText`. Цель — клетка или область (`zoneId`: персонаж встаёт на первую свободную клетку области — `zoneTargetCell` в `content/case-utils.ts`, подставляет стор перед применением эффектов; ключ области при переименовании в эффектах обновляется). Сцена сообщает настоящее место через `SceneHost.setNpcPlace`.
- Ключи (id) никогда не меняются сами: только вручную в `KeyField`; у сущностей верхнего уровня — с подтверждением и заменой всех ссылок (`renameKey` в `apps/client/src/editor/keys.ts`).
- Пользователь играет во встроенном браузере VS Code (Linux): нативные `<select>` там не открываются, перерисовка капризна — избегать `transform` на hover и трюков с остановкой анимации.

- Вкладки в конструкторе — один компонент `apps/client/src/editor/Tabs.tsx` (`variant="bar"|"inline"`, стили `editor/styles/tabs.css`); своих `*__tab` не заводить.
