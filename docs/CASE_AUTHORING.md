# Как собирать новое дело по приговору

Сводка по опыту дела 003 («Сцепка на стоянке», ч. 2 ст. 143 УК РФ). Источник правды по формату — `shared/case.ts` (Zod-схема); образцы — `apps/client/src/content/cases/case-002.json`, а сам скрипт-сборщик дела 003 лежит в `working/cases/build-case-003.cjs` (его удобно копировать как заготовку).

## 1. Порядок работы

1. **Выбрать приговор** из `working/case_refs/` (файлы вида «Приговор по NNN.md» — по статье; файлы с подчёркиваниями — другие подборки, не путать).
2. **Выписать из приговора факты** (одна страница заметок, не в репозиторий):
   - кто виновный и в какой должности; кто потерпевший; что сделано/не сделано;
   - нормы, которые нарушены (точные пункты), и **чем они подтверждены** (документы, экспертизы, показания);
   - линия защиты и опровергающее её (чем виновный оправдывается, почему не работает);
   - вина потерпевшего или третьих лиц — и почему она не снимает ответственности;
   - наказание (только для разбора в `solution.explanation`).
3. **Вымышленные имена и организации.** Реальных людей и компаний не использовать; фабула может опираться на практику (указать в `solution.sources`).
4. **Спроектировать** (см. разделы 2–3), затем написать сборщик-скрипт в scratchpad, сгенерировать `apps/client/src/content/cases/case-NNN.json`.
5. **Проверки** (по порядку):
   - `pnpm validate:cases` — целостность; чинить по сообщениям (`evidence x: …`, `location l/object o: …`);
   - `pnpm touch:cases` — ОБЯЗАТЕЛЬНО после правки любого `cases/*.json`;
   - `pnpm typecheck`, `pnpm test` (`game.test.ts`, `editor.test.ts`: валидность, баллы, прохождения), `pnpm build`;
   - по желанию открыть `/editor/case-NNN` и пройти дело вручную через `window.__game.actions` (скриншоты не нужны).
6. Закоммитить (сообщение по-русски, в стиле репозитория), обновить `working/plans/ROADMAP.md`, если дело — часть плана.

## 2. Состав дела (ориентир по объёму)

| Часть | Сколько | Замечания |
|---|---|---|
| Локации | 2 | первая — «штаб» (кабинеты), вторая — место происшествия; связаны зонами `exit` в обе стороны |
| Персонажи | 4–6 | виновный, руководитель, специалист по теме, свидетель, коллега потерпевшего; у каждого `look` из `LOOKS` |
| Улики | 14–18 | документы (high), нормативный акт, видео/экспертиза, показания (`testimony`); ложные показания — `reliability: "low"` |
| Диалоги | по одному на человека | ветвление флагами: виновный сначала лжёт → предъявление улик → признание |
| Сопоставления | 5–7 | цепочки: обязанность → факт → норма → связь → вина; ровно 2 материала в каждом (улики или id других сопоставлений) |
| Подсказки | 3 | штрафы 5/7/10, от общей к конкретной |
| Вопросы | 5 | сумма баллов **ровно 100**: right 30, violation 15, qualification 15, responsible 20, evidence 20 |
| События (`events`) | 5–7 | хронология; даты `ММ-ДД[Tчч:мм]` |

## 3. Правила содержания

- **Юридическая точность.** Любые «Важно»-выводы — только из приговора. Номера статей, пунктов правил, актов — как в источнике. Конституционное право (`right`) выбирать то, что реально нарушено; близкие по смыслу варианты — частичные баллы с объяснением.
- **Ключевая «ловушка» дела.** В каждом деле должен быть нюанс, который игрок может ошибочно счесть оправданием (локальный стандарт вместо федеральной нормы, вина потерпевшего, формальное соблюдение инструктажей). Отдельное сопоставление + пояснение в `lawReference.notes`.
- **Подведение к ответу улики-доказательства.** Вопрос `evidence` (multi): очки у ключевых улик, нулевые у нейтральных, **отрицательные** у ложных показаний. Сумма положительных ≥ 20.
- **Улики не должны раскрывать приговор.** Текст улики — факты, а не вывод; вывод получает игрок через сопоставление.
- **Кто «виновен»** определяется `solution.responsibleCharacter` и вопросом `responsible` (источник `characters`): у виновного — полные баллы, у смежных лиц — 0–3 с объяснением.
- **Квалификация** — вариант с «признаками преступления» (выводит суд). Не писать «виновен»: писать «содержит признаки».
- **Тексты — по-русски**, протагонист — дознаватель; без эмодзи.

## 4. Карта и объекты

- Легенда символов тайлов копируется из `case-002.json` (`legend`); размер карты 30×17 (админ) и свободный для улицы; границы стен — `#`/`B`/`F`, проёмы — `D`, окна — `W`.
- Настенные предметы (`board`, `poster`, `clock`, `cabinet`, `bookshelf`) ставятся в ряд стены (y=0–1 или y карты у нижней стены); напольные — внутри комнаты, не в проёмах.
- Вход в кабинет — предмет `door_h`; выход — **зона** с действием `exit` (`{kind:"exit", to, spawn:{x,y}}`).
- Улика берётся осмотром предмета: `onInteract: [{type:"addEvidence", evidenceId}]`; одну улику — один предмет. Нужная в диалоге улика — эффект узла диалога.
- У каждого `id` — латиница, snake_case; кириллица только в `name`/`text`.

## 5. Диалоги

- Узел: `{id, text, mood, effects, choices}`; вариант: `{id, text, next, requires?, effects}`; `next: null` — конец разговора.
- Эффекты: `addEvidence`, `changeVariable` (`on`/`off`), `addCharacterNote`, `message`, `startDialogue`, `travel`, `failCase`.
- Типовая схема допроса виновного: нейтральные вопросы → «ложная версия» (флаг `…_lied`, показание с `reliability: low`) → предъявление трёх улик (`requires.evidence` + флаг) → признание (`…_admitted`, улика high) | закрытие (`…_closed`) при грубости.
- У любого используемого флага должно быть название в `flags` (валидатор). Ключи флагов, счётчиков и перечислений не пересекаются; id сопоставлений тоже ставим флагами (`effects: [on(id)]`).

## 6. Сопоставления и вопросы

- `deductions[].evidenceIds` — **ровно 2** id; допускаются id других сопоставлений (цепочки без циклов); одинаковые пары не повторять.
- 3 варианта (`a/b/c`), один `correct`, у каждого `feedback`.
- Вопрос `evidence` с отрицательными очками — допустимо; порог `minScore` по умолчанию 75.
- Предметы (`kind: "item"`) в сопоставления и вопросы про улики не попадают.

## 7. Типичные ошибки

- сумма `maxPoints` ≠ 100 или баллы вариантов превышают `maxPoints`;
- ссылка на несуществующий id (улика в `requires`, персонаж в `relatedCharacters`, событие в `relatedEvents`, локация в `exit.to`);
- у флага нет названия; два флага с одним id; id сопоставления совпадает с id флага без записи в `flags`;
- предмет или NPC в клетке стены / вне карты; зона `exit` без `spawn` или со `spawn` в стене;
- забыт `pnpm touch:cases` — игроки со старыми сохранениями не получат предупреждение;
- ссылки в `lawReference.url` нужны только на официальные источники (КонсультантПлюс/Гарант), иначе без `url`.

## 8. Чек-лист перед коммитом

- [ ] `pnpm validate:cases`, `pnpm test`, `pnpm typecheck`, `pnpm build` — без ошибок
- [ ] `pnpm touch:cases` выполнен
- [ ] Сумма баллов = 100, при идеальном ответе — 100
- [ ] Улика с признанием достижима (все требуемые для неё улики добываются в игре)
- [ ] Все улики из `keyEvidence` достижимы
- [ ] Нет реальных имён и организаций; источник указан в `solution.sources`

## 9. Планировка: не копировать карту прошлого дела

- Не переносить `tiles` и расстановку 1 в 1 из другого дела (в деле 003 так вышло с общежитием — пришлось переделывать): менять размеры и число комнат, положение дверей и выхода.
- Полы: комнаты одного назначения (кабинеты) — одно покрытие; коридор, холл, улица — своё. Внутри холла можно выделить зону другим покрытием.
- Расстановка: у разных комнат разный «рисунок» (стол у окна / у стены, переговорный уголок, диван у входа, стеллажи вдоль стены) — но реалистично: стул за столом (на клетку севернее), настенное (часы, постеры, доски) в ряду стены, перед дверью (клетка перед проёмом) свободно.
- Кровати, диваны и другая мебель — на полу, не вплотную к стене в ряду y=1, если это не шкаф/стеллаж.
- Декор («филлеры») — по 8–12 предметов на комнату, id `f_<локация>_<спрайт>_<n>`; уникальны в рамках дела.
