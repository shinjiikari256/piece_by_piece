# По кусочкам

Браузерная 2D-игра-расследование для студентов-юристов: учебные дела по разным отраслям права.
Игрок — дознаватель: проверяет заявление о преступлении, осматривает место,
опрашивает людей, устраивает очные ставки и даёт юридическую оценку.
Работает полностью локально, без бэкенда.

```bash
pnpm install
pnpm dev        # http://localhost:5173 — сайт и игра, конструктор: http://localhost:5173/editor
```

## Команды

| Команда | Что делает |
|---|---|
| `pnpm dev` | дев-сервер |
| `pnpm build` | проверка типов и сборка в `dist/` (статикой можно раздавать с любого сервера или открыть через `pnpm preview`) |
| `pnpm typecheck` · `pnpm lint` | проверка типов; ESLint (в том числе запрет нативного `<select>`) |
| `pnpm test` | тесты: валидность сценариев, баллы, полное прохождение обоих дел, сохранение, очные ставки, конструктор, сервер (PGlite) |
| `pnpm test:e2e` | сквозные тесты в браузере (playwright-core + свой Vite и сервер на PGlite): прохождение дела, перезагрузка, окна, конструктор, вход |
| `pnpm validate:cases` | проверка всех JSON-сценариев |
| `pnpm db:up` / `pnpm server:dev` | PostgreSQL в Docker и API-сервер (первый администратор — из `ADMIN_LOGIN` / `ADMIN_PASSWORD`); без сервера игра работает локально |
| `pnpm export:offline` | один `.html` с делами для работы без сети: `--cases=case-001,case-002` (или путь к `.json` из конструктора), `--out=delo.html` (файлы складываются в `offline/`) |
| `pnpm generate:case --topic=privacy --difficulty=medium --evidence=6 --characters=4` | черновик нового дела через Claude API |

## Управление

| Клавиши | Действие |
|---|---|
| `WASD` / стрелки | движение (у дверей персонажа «подтягивает» в проём) |
| `E` / `Enter` / `Пробел` | осмотреть / заговорить |
| `M` · `H` · `N` · `V` · `I` | материалы дела · подсказка · заметки · вынести решение · «Как играть» (работают и в русской раскладке) |
| `1–9`, `↑` `↓` | выделить вариант в диалоге; `Enter` — выбрать (без выделения — первый ещё не заданный вопрос) |
| `←` `→` | вкладки журнала; вопросы в окне решения |
| `Enter` | основная (синяя) кнопка в любом окне |
| `Esc` | закрыть окно (в том числе окно решения — ответы сохраняются); в игре без окон — выход в меню с сохранением или без |

По объектам, людям и полу можно кликать (и тапать): персонаж сам дойдёт и начнёт взаимодействие.

**Телефон и планшет.** На сенсорном экране появляются джойстик и кнопка действия; тап по полу или предмету тоже работает.
Если карта целиком не помещается крупно, камера приближается и следует за дознавателем.

## Механики

- **Окна** — всё в игре открывается папкой с вкладкой и крестиком справа: дело, подсказки, заметки, осмотр, разговор; решение — синяя папка, где по вкладке на вопрос (галочка — ответ есть) и итоговая вкладка «Решение» со всеми ответами.
- **Сохранение** — автоматически в localStorage, отдельно для каждого дела; продолжить можно с главной или из списка дел.
- **Заданные вопросы** отмечаются ✓; переспросить можно, но собеседник будет недоволен.
- **Сильные реплики** («предъявить») открываются, когда в деле есть нужная улика или установлен нужный факт.
- **Сопоставление** — доска: 2–3 улики → вопрос → установленный вывод (карточкой в материалах дела).
- **Очная ставка** — попросите свидетеля пойти с вами (он идёт следом, в том числе в другие локации) и заговорите с тем, кого он изобличает: начнётся разговор втроём. Неосторожная реплика может её сорвать.
- **Несколько локаций** — переходы через подписанные выходы на краю карты (дело №002: 4 этаж ↔ вахта).

## Как устроено

```
apps/
  client/                браузерная игра и конструктор (Vite): index.html, vite.config.ts, public/
    src/
      content/
        cases/*.json     сценарии
        validate.ts      смысловые проверки: ссылки, достижимость улик, сумма баллов = 100…
        repository.ts    CaseRepository — источник дел (сейчас JSON из бандла)
      state/store.ts     состояние игры и все действия игрока
      game/              Phaser: сцена, процедурный pixel-art, мост к React
      ui/                React-интерфейс: меню, журнал, диалоги, сопоставление, финал, разбор
      editor/            конструктор дел (раздел /editor)
  server/                API (Hono + PostgreSQL + Drizzle): src/, drizzle.config.ts
shared/                  код клиента и сервера: Zod-схема дела, условия, баллы, судья, контракт API
scripts/                 generate-case, validate-cases, export-offline
```

- **Phaser** рисует только локацию и персонажей; всё остальное — React поверх canvas.
- Графика рисуется кодом (`apps/client/src/game/art.ts`): никаких внешних ассетов и лицензий.
- Чтобы брать дела из API, достаточно второй реализации `CaseRepository` (fetch + `validateCase`).
- В формате улик есть поле `media` (фото, сканы, аудио, видео) — под будущие мультимедийные материалы; игра от него не зависит.

## Как добавить дело

1. Положите JSON в `apps/client/src/content/cases/` (за основу удобно взять `case-001.json`).
2. `pnpm validate:cases` — валидатор назовёт битые ссылки, недостижимые улики, неверные суммы баллов.
3. Некорректное дело не попадёт в игру (ошибка будет в консоли браузера).
4. Поменяли дело вручную — обновите `updatedAt`: `pnpm touch:cases case-002.json` (или вручную ISO-время).
   Сохранения игроков, сделанные на другой версии дела, не загружаются: игра предупредит и предложит начать заново.
   Конструктор и генератор ставят `updatedAt` сами.

### Генератор

`pnpm generate:case` вызывает Claude (`claude-opus-5-5`) со structured outputs по той же схеме,
прогоняет результат через валидатор и до двух раз просит модель исправить ошибки.
Нужен `ANTHROPIC_API_KEY`. Без доступа к API игра продолжает работать на готовых JSON.

Включён серверный fallback (`fallbacks: "default"`): если основная модель откажет в ответе,
запрос автоматически продолжит другая модель.

Сгенерированное дело получает `review.status = "draft"` и помечается в игре как непроверенное.

## Юридическое содержание

Сценарии — учебные. Перед мероприятием формулировки проверяет преподаватель; после проверки
поставьте в файле дела `review.status = "reviewed"`.
В игре квалификация подаётся как «возможная», с разграничением: затронутое право,
нарушение права, административное правонарушение, преступление, гражданско-правовой спор,
дисциплинарное нарушение.

## Конструктор дел

раздел «Конструктор дел» (`/editor`, ссылка в шапке у преподавателя):

- формы для всех разделов дела, ссылки на персонажей/улики/узлы — выпадающими списками с поиском;
- облики персонажей и предметы выбираются плитками с картинками;
- карта: 19 видов пола и стен (паркет, кафель, мрамор, трава, кирпич, стекло…), 36 предметов, 20 обликов персонажей; люди, старт, выходы между локациями, перетаскивание, размер карты;
- граф диалогов: узлы двигаются мышью, связи «вариант → узел» тянутся от кружка варианта, автораскладка;
- живая валидация (кнопка со счётчиком ошибок), отмена/повтор `Ctrl+Z` / `Ctrl+Shift+Z`;
- «Запустить» — открывает черновик в игре (черновики хранятся в localStorage и видны в списке дел с пометкой);
- импорт/экспорт JSON — готовое дело кладётся в `apps/client/src/content/cases/`.

## Перед запуском
- Показать юристу и ответственному за персональные данные текст согласия (`shared/api.ts`) и порядок хранения данных студентов.
- Проверить название «По кусочкам» по реестру ФИПС (классы 9 и 41).
- Подробности — в `working/plans/PLAN.md`.
